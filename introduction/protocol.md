# 区块与本机网络协议 v1

当前实现支持单节点运行和本机 TCP 多进程连接、旁支保存及累计工作量选链。区块头和创世块与单节点阶段保持一致。教育教学用途和功能边界见[根 README](../README.md)。

## 创世配置

共享配置为 [`codes/config/genesis.json`](../codes/config/genesis.json)，必须且只能包含 `version`、`network_id`、`target`、`genesis_nonce`。

- 版本：整数 `1`。
- 网络标识：`coap-edu-pow-001`，恰好 16 个 ASCII 字节。
- 目标值：`0000ffffffffffffffffffffffffffffffffffffffffffffffffffffffffffff`，正整数的 64 位小写十六进制表示。
- 创世 Nonce：`24452`。

创世块高度为 0，父哈希为 32 个零字节，节点标识为 16 个零字节。它也满足 PoW，固定 SHA-256 为：

```text
0000afc5ce4192fbc256c769acc9bb16cc9010bb585056cc355b828c9deb65fc
```

所有节点使用相同创世配置。配置无效时直接报错，不自动重新生成创世块或降低难度。

## 确定性编码

区块头共 114 字节，格式为 `>H16s32sQ16s32sQ`，整数统一无符号大端编码：

| 偏移 | 字段 | 字节数 | 约束 |
| --- | --- | --- | --- |
| 0 | version | 2 | 当前只支持 1 |
| 2 | network_id | 16 | 与配置一致 |
| 18 | previous_hash | 32 | 父块哈希的原始字节 |
| 50 | height | 8 | 当前上限为 `2^63 - 1`，与 SQLite 整数范围一致 |
| 58 | node_id | 16 | 新数据目录生成 UUID v4，重启后保持；全零值仅供创世块使用 |
| 74 | target | 32 | 全网统一目标值 |
| 106 | nonce | 8 | `0` 到 `2^64 - 1` |

对完整 114 字节执行一次 SHA-256，不包含 JSON、时间戳、交易或额外载荷。`node_id` 区分候选输入，不是账户、认证凭证或出块许可。

## PoW 与追加验证

哈希按大端无符号整数解释，必须满足 `SHA256(header) <= target`。单进程参考实现从 Nonce 0 起顺序搜索，暂未加入多核、C/C++ 或 ARM 加速切换。

新块必须同时满足：版本、网络、目标值与配置一致；高度为父高度加 1；父哈希等于当前链头哈希；节点标识非零；PoW 有效。字段类型、字节长度和整数范围在构造时检查。

已保存哈希的重复区块不追加、不计数。存储层接受已知父块上的有效后继，包括旁支；未知父块不能直接进入存储。网络层收到缺少父块的有效头部后，向发送者请求该块所在链的有序分批数据，再逐块验证。

## SQLite 与恢复

每个数据目录包含一个 `chain.sqlite3`：

- `metadata`：保存该目录的节点标识。
- `blocks`：按高度保存区块头和实际哈希；高度为主键，哈希唯一。
- `block_graph`：按哈希保存全部已经验证的区块，包含旁支。`blocks` 只表示当前选中的链。

仅数据库文件不存在时初始化。已有文件必须具有有效结构、节点标识和非空链。启动验证当前链和所有旁支，包括存储高度、头部与哈希、固定创世块、前后连接、PoW 及选中链的最大累计工作量。

旧单节点库的 `user_version=0` 在完整验证后事务性升级为 1：新增 `block_graph` 并复制已有区块，不改变节点标识、链头或累计量。当前链损坏时先报错，不执行升级；不支持的 schema 版本直接拒绝。

累计量直接取选中链的高度，创世块不计入。保存区块和切换当前链使用同一个 SQLite 事务，提交成功后才更新内存状态。旁支数不累加到计数里。错误配置、坏库、缺失创世块或区块损坏均报错，不覆盖或重建已有数据。

同一数据目录仅供一个进程使用。后续双节点必须使用不同目录。

## 累计工作量与平局

创世块工作量记为 0，每个非创世块的协议工作量为 `floor(2^256 / (target + 1))`。累计工作量沿已验证的父链求和；不接受对端声明的工作量或高度作为选链依据。

新分支只有累计工作量严格更高才替换当前链。固定目标值下，这也意味着该分支区块更多。平局保存两条分支并保留当前链头，等后续区块打破平局；因此平局状态下两端高度可能相同、哈希不同。

## TCP 消息与同步

不指定 `--listen` 时不开启网络。指定时只允许明确的 IPv4 回环地址或 RFC1918 私网地址；拒绝 `0.0.0.0`、公网地址和域名。`--peer` 可重复，必须同时指定 `--listen`。不自动扫描或发现节点，不向外部服务请求地址。

传输使用以换行结束的 JSON，每条消息含换行最多 16384 字节，字段集合严格匹配类型。区块用 114 字节头部的小写十六进制传输；JSON 不参与区块哈希。

| 类型 | 字段（除 type） | 用途 |
| --- | --- | --- |
| hello | version, network_id, genesis, node_id, head | 双向握手，检查版本、网络和固定创世哈希；拒绝自身及全零节点标识 |
| head | hash | 通知当前链头 |
| block | header | 广播一个已验证区块 |
| get_chain | head, locator | 请求指定链头之前已知共同祖先之后的区块 |
| chain | head, headers | 回复至多 32 个有序区块头 |

握手超时为 5 秒。locator 最多 64 个哈希，从已知链头沿父链指数回退至创世块。接收方使用自己的区块图识别共同祖先，每批逐块验证，未达到目标链头则继续请求下一批。无共同创世块、非法消息、无效区块和不匹配的回复均断开该连接并输出原因。

显式配置的 peer 在连接失败或 TCP 检测到断开后每秒尝试重连，握手时重新比较链头并补齐区块；不会清空本地状态或切换到其他网络服务。链头变化后，计算任务丢弃旧候选块，改在新链头继续搜索。

网络模式每批计算最多 4096 个 Nonce 后让出事件循环，避免同步被整个搜索任务阻塞。它仍为单进程参考计算，不是多核加速。

当前为受控教学网络中的明文 TCP，无密码身份认证。节点标识不等于认证；PC、Pi、真实 Wi-Fi 断网及恶意环境下的长期运行尚未验证。

## 终端含义

- `START`：恢复后的高度、累计量、链头与节点标识。
- `BLOCK`：新块高度、累计量、哈希、成功 Nonce、尝试次数和搜索耗时。
- `STOP`：本次运行结束后的高度、累计量与链头。

`--blocks N` 表示额外计算 N 块，默认 0。新目录即使指定 0 也初始化创世块，已有目录指定 0 只验证并显示状态。负数在参数解析阶段拒绝。

`attempts` 与 `compute_seconds` 是一次随机出块搜索的数据，不能替代固定工作量的性能基准。

网络模式完成 `--blocks N` 次本地计算后保持监听，通过 Ctrl+C 停止；收到的区块不抵扣本地计算次数。输出还包含 `PEER_CONNECTED`、`SYNC`、`SYNC_DONE`、`RECEIVED`、`COMPUTED`、`REORG`、`COMPUTE_DONE` 和断线原因。`SYNC_DONE` 表示已获取请求的链头；等工作量时不保证将该链头选为当前链头。
